# MinerU 4.1.3 vs general-purpose VLM (Qwen3.5-0.8B) — academic PDF

Archetype: `pdf-academic` · Date: 2026-11-01 · Protocol: [METHOD](../METHOD.md)

## Question

Can a small general-purpose multimodal LLM replace a dedicated parsing pipeline by "just reading" page images?

## Contestants

| | MinerU 4.1.3 (GPU, cu129) | Qwen3.5-0.8B (bf16, vLLM 0.29) |
|---|---|---|
| Form | dedicated pipeline: layout + OCR + formula small models + 1.2B document-tuned VLM (Qwen2VL arch, weights baked in) | general multimodal LLM, end-to-end per-page transcription with a fixed prompt |
| Input | PDF | page images rendered at scale=2 (pypdfium2), same PDF |
| Precision | bf16 | bf16 |

Document: a 13-page two-column hydrology paper (public demo PDF), tables + inline/display math + figures.

## Results

### Quality — blind judge, position-swapped (4 rounds total: 2 per document half)

**MinerU wins 4/4 overall.** Position swap validated: cited defects moved with the system.

Cited defects of the VLM route, stable across rounds:

- duplicated abstract; whole sections missing (e.g. Background block)
- tables collapsed into garbled rows; table footnotes lost
- formulas missing normalization denominators, wrong subscripts
- chapter misordering
- **2 of 13 pages truncated** at the 4096-token output cap (figure-dense pages) — recorded as `finish_reason=length`

### Speed (RTX 4060 8GB laptop)

| | wall time |
|---|---|
| MinerU CLI cold (engine start included) | 115s / 13 pages |
| MinerU warm API (model resident) | 9s / 13 pages (**1.51 page/s**) |
| Qwen3.5-0.8B per-page transcription | 4–9 s/page, 176s / 20 pages total batch |

The dedicated pipeline is not only more accurate but **faster at serving time**.

## Verdict

General small VLMs are not document transcribers: no global reading order, output caps truncate dense pages, structure collapses. Their multimodality is best spent on "look and answer" tasks. For PDF→structured-markdown production, use a pipeline.

## Reproduction notes

- Fixed prompt (zh): "transcribe this page fully to Markdown: heading levels, paragraphs, lists; tables as Markdown tables; formulas as LaTeX; strict reading order; Markdown only."
- MinerU outputs stripped of embedded base64 images before judging; VLM outputs stripped of code fences.
- Judge: deepseek-v4-flash, thinking disabled, temperature 0; line-based verdict format; winner accepted only if stable across position swap.
- Full local artifacts (page images, both transcripts, judge transcripts): retained by the authors; numbers above are reproducible with the protocol on the same public demo PDF (`opendatalab/MinerU` repo, `demo` directory).
